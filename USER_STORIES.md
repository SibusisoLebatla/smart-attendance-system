# 📌 User Stories Table  

| Story ID | User Story | Acceptance Criteria | Priority (High/Medium/Low) |
|----------|-----------|---------------------|----------------------------|
| US-001 | As a student, I want to register my attendance online so that I don’t need to sign paper sheets. | Attendance is successfully recorded in the system and visible to instructors. | High |
| US-002 | As an instructor, I want to view students’ attendance records so that I can track class participation. | The attendance report is generated correctly and displayed in a dashboard. | High |
| US-003 | As an admin, I want to add and remove users so that only authorized people can access the system. | Users can be successfully created, updated, and removed. | High |
| US-004 | As a student, I want to check my attendance history so that I can verify my records. | The system displays the correct attendance history for the logged-in user. | Medium |
| US-005 | As a student, I want to receive a notification if I forget to register my attendance so that I don’t miss attendance points. | The system sends an automated reminder if attendance is not recorded. | Medium |
| US-006 | As a system, I want all attendance data to be encrypted so that user privacy is protected. | Attendance data is stored using AES-256 encryption. | High |
| US-007 | As an instructor, I want to export attendance reports to Excel so that I can analyze data offline. | The system allows exporting attendance records to .xlsx format. | Medium |
| US-008 | As an admin, I want the system to support at least 1,000 students at a time so that it remains scalable. | The system successfully handles 1,000 concurrent users without crashes. | High |
